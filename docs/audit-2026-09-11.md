# Installation and application audit — 2026-09-11

The installation failure was reproduced on the actual Kali host. The corrected
installer completed successfully, Ollama became healthy, and the host CLI
produced JSON, HTML, PDF and SARIF reports using all ten analyzers.

## Root cause and recovery

The original process was waiting inside `docker compose up -d ollama`.
Compose 2.40.3 detected a configuration change on `dede_ollama-data` caused by
new volume labels. It asked whether to recreate the volume, warning that its
data would be lost. The installer redirected both normal output and the
diagnostic stream at this call site, hiding the question indefinitely.

Restoring the original volume definition removed the recreation request in a
Compose dry run. The corrected startup then created and started the Ollama
container successfully. The existing volume was retained. No model download or
volume deletion was performed. The available model list is currently empty.

The installer now exposes startup progress/errors, bounds startup to 300 seconds
and API readiness to 90 seconds, closes startup stdin, and does not repeat a
failed startup in its preflight. Existing scanner images are verified before
the optional AI step. `DEDE_OLLAMA_START_TIMEOUT` and
`DEDE_OLLAMA_READY_TIMEOUT` override the limits.

The host environment also contained an unwritable `.venv` owned by another
user. The corrected installer preserved it as `.venv-backup.SWwZ5Q` and created
a working replacement. Broken environments are preserved instead of deleted.
Backup directories are excluded from discovery, Git and Docker build context.
The installer uses the current interpreter path instead of stale activation
paths left by moving a checkout.

## Verification

The final complete suite passed **488 tests in 179.46 seconds**, with **76%
Python statement coverage** (5,074 statements, 1,212 uncovered). The original
suite had 459 tests; this audit added 29 regression cases. No tests were skipped
in the final Docker run.

- Scanner and test Docker images built successfully, including package wheel
  construction and validation of 138 custom Semgrep rules.
- Ruff application lint, mypy, ShellCheck, Bash syntax and `git diff --check`
  passed. `pip check` reported no broken requirements in the test image.
- `bash install.sh -y` completed with exit code 0, preserving the old venv and
  skipping the unrequested large model download.
- The actual host CLI scanned `tests/vulnerable_samples`: six discovered files,
  73 lines, 38 findings, and SUCCESS from all ten analyzers. JSON/HTML/PDF/SARIF
  were produced under `/tmp/dede-audit-proof`. PDF signature and SARIF finding
  count were checked, and integration tests check example-secret redaction.
- `dede doctor --output /tmp/dede-doctor-proof` returned 0. Required components
  passed. Ollama was reachable; the configured model was absent.
- The final scanner image, with native rules 0.3.1, also scanned the samples
  using `docker run --network none --read-only`, dropped capabilities and UID
  1000. All ten analyzers returned SUCCESS. It produced **35 findings** and all
  four report formats under `/tmp/dede-offline-proof`. The decrease from 38
  reflects the corrected credential rule. PDF signature, SARIF count, rule
  version, analyzer statuses and example-secret redaction were verified.

Reproduce the comprehensive tests without giving the test container networking:

```bash
docker compose --profile test build test
docker compose --profile test run --rm -e COVERAGE_FILE=/tmp/.coverage test \
  -p no:cacheprovider -q --cov=dede --cov-report=term --durations=10
```

The test service uses `network_mode: none`, a read-only source mount, a read-only
container filesystem and a non-root user. Integration tests exercise real
Semgrep, Bandit, Ruff, Gitleaks, Go tools and PDF rendering. AI response handling
uses controlled responses; AI static verification runs the real static engines.

## Performance and self-scan evidence

The actual sample scan recorded 16.92 seconds through analysis/normalization;
this metadata duration excludes report rendering. The largest component was
Semgrep at 11.78 seconds. These are single observations, not a throughput or
improvement guarantee.

A source audit covered 85 discovered files and 10,023 Python lines in 16.81
seconds before the credential-rule correction. It exposed 647 credential-rule
hits, mostly unrelated assignments. Running the corrected rule against the
source reduced that to one enum-label assignment requiring contextual review.
The fixed duplicate analyzer independently processed 68 Python files / 10,023
lines in 1.60 seconds, reporting 101 groups / 126 findings. Candidate and window
limits remain in place. No speedup claim is based on these measurements.

Self-scan alerts are not automatically confirmed defects. Examples reviewed
include a redacted private-key placeholder, a loader variable bound to PyYAML's
safe loader, and subprocess argument lists passed with shell execution disabled.
These require contextual interpretation. Quality heuristics also report long
functions, nesting and repeated code; this audit does not claim zero remaining
maintainability work or zero false positives.

## Limits

Passing tests and coverage are evidence for the exercised cases, not proof that
every possible project, rule, path or failure mode works. No model is installed,
so actual model inference, model quality and large downloads were not validated.
GPU execution, other CPU architectures, fresh installs on other distributions,
and destructive uninstall were not exercised. Existing user changes were
preserved; no commit or history rewrite was made.

If the original terminal still waits at its hidden prompt, cancel that old
process with Ctrl+C. The updated installation is usable with:

```bash
dede scan . --no-ai
```
